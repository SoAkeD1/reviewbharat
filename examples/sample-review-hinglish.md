### [CRITICAL] SQL Injection Vulnerability
`app/db.py:14`

Yahan user input `name` seedha string concatenation se SQL query mein ja raha hai. Isse attacker database mein arbitrary queries chalakar data leak ya corruption kar sakta hai.

**Suggestion:** Parameterized queries use karo. Example: `cur = conn.execute("SELECT * FROM users WHERE name = ?", (name,))`

### [CRITICAL] Use of eval()
`web/calc.js:3`

`eval()` runtime mein arbitrary code execute karta hai. Agar `expr` user-controlled input hai toh Remote Code Execution (RCE) vulnerability ban jati hai.

**Suggestion:** `eval()` avoid karo. Agar simple math expressions chahiye toh `mathjs` jaisa library use karo ya custom parser likho.

### [HIGH] Hardcoded API Key
`app/db.py:12`

API key source code mein hardcoded hai. Agar repo public ho ya log access ho jaye toh secret leak ho jayega. Best practice hai ki secrets environment variables ya secret manager se load karo.

**Suggestion:** `API_KEY = os.environ.get("API_KEY")` use karo aur `.env` file ya CI/CD secrets mein value rakho.

### [MEDIUM] Bare Except Clause
`app/db.py:17`

`except:` block koi specific exception handle nahi karta, isse debugging mushkil hoti hai aur unexpected errors silently swallow ho jate hain. Return value `None` ho jayega bina kisi log ke.

**Suggestion:** Specific exception catch karo, e.g., `except sqlite3.Error as e: logger.error(e); return None`
